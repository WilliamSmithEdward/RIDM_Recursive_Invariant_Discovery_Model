# Run Q005

- Date: 2026-08-30
- Category: Computer Science/AI (numeric formats)
- Answer type: exact match
- Image: none
- Result: incorrect per the official key; the key itself is demonstrably defective
- Stated confidence before reveal: about 70 percent, with a named residual one unit wide

## RIDM Application

The task was a deterministic simulation under three numeric formats. The attempt derived
each pathway step by step, identified the single genuine rounding event in the mid-precision
format, verified the high-precision path exactly, and cross-checked the low-bit path under
the two plausible readings of its underspecified value grid, which converged on the same
committed answer. The residual (one alternative quantization choice) was stated and spanned
one unit.

The revealed official value lay far outside the modeled residual. Inspection of the official
rationale found multiple objective internal inconsistencies: a term of the stated input
sequence dropped during summation, a multiplication whose printed result is arithmetically
impossible for its own printed operand, a division whose printed result is wrong for its own
printed operands, and a low-bit pathway that simultaneously assumes integer-only wrapping
and fractional storage. No consistent semantics reproduces the official chain.

## Framework Observations

- An answer key is a reported claim, not ground truth. This run produced a live case of the
  specification's tool-result literalism failure mode pointed at a grader: accepting the
  oracle's verdict without checking its internal consistency would have updated the model on
  a defective signal.
- Section 41 makes user feedback authoritative about intent but only evidentiary for
  external facts. The same discipline must apply to any external correction signal,
  including authoritative-looking validation infrastructure: check well-formedness before
  reopening.
- Surprise decomposition worked as a detector: the error lay entirely outside the stated
  residual, which is itself evidence that the observation came from a different generator
  than the modeled task, and prompted verification of the verifier rather than blind
  self-correction.
- Honest status requires two tracks here: the protocol-level outcome (scored incorrect) and
  the epistemic finding (the item is defective, with checkable evidence). Collapsing either
  into the other would misreport.

## Lessons

1. Treat correction signals and answer keys as reported evidence; run an internal-consistency
   check on the verifier before letting a contradiction reopen the model.
2. When an error falls entirely outside the stated residual, suspect a different generator
   (a defective oracle, a changed task, an unmodeled regime) before revising the reasoning
   that produced the residual.
3. Record dual-track outcomes when validation infrastructure fails: the graded result and
   the documented defect are both material, and neither replaces the other.
