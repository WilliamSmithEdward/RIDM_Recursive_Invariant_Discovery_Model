## RIDM 18 Application

A memory-golf twist on a beginner-level matrix scanning problem: given tight
stated ranges on the matrix size and the stored digit, find the smallest number
of bytes the variables of a solving C program need. The frame question was what
counts as a variable; the committed frame charged declared objects only, with
expression temporaries free, and read the stated size bound as load-bearing
twice over: it makes every needed quantity fit a nibble and makes a cell's
linear index fit a single byte.

The rigorous route was a bound-plus-witness pair. The lower bound counted the
distinguishable live states a scanner must carry mid-stream (summing the square
of the size over its admissible values), which exceeds one byte's 256 states,
so one byte is impossible. The witness was an explicit two-byte construction:
one packed variable holding size, linear position, and digit in 4-8-4 bits,
with input classified through hardcoded switch cases so no character buffer is
ever declared, and the output quantities computed inside the print call's
argument expressions. Both anchor cases (the degenerate size and the classic
original instance) checked out.

The referent check classified the item casually authored (wrapper prose,
typos), capping the band at medium. Rivals at three bytes (unpacked byte
variables) and four bytes (a single int, or one byte per output value) were
computed to parity and lost: three fails the stem's literal "smallest needed"
criterion once the two-byte witness exists, and four leaves the stated size
bound unconsumed. The key matched the committed answer, and its published
rationale is the same nibble-packing argument in bitfield form.

## Framework Observations

- Capability consumption did real selection work. Treating the stem's tight
  numeric ranges as granted capabilities that must be consumed (the size bound
  exactly saturating one byte of positions, the digit bound fitting a nibble)
  discriminated between rival keys: candidates under which those bounds go
  unconsumed were demoted for exactly that reason.
- The bound-plus-witness discipline carried the commitment. Neither half alone
  would have: the witness without the bound leaves the smaller answer live,
  and the bound without the witness leaves the larger rivals live.
- The literal-criterion rule resolved the author-model tension. The stem asks
  for the smallest number needed, so a provably achievable minimum outranks a
  model of a sloppier author who might have keyed an unpacked count; the
  author model was used only to cap the band, not to move the answer.
- The key's construction differed from the committed witness (per-cell row and
  column nibbles versus a linear position byte) while agreeing on the total,
  a reminder that the graded claim is the count, not the construction, and
  that equivalent-form tolerance matters when predicting exact-match keys.

## Lessons

No new framework lesson. Capability consumption, bound-plus-witness
validation, and canonical-criterion precedence, all existing RIDM 18
disciplines, selected the answer and the band.
