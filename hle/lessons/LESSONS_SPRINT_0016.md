# Framework Lessons - Sprint 0016 (Q000151 to Q000160)

Distilled, content-free lessons from the sprint's runs in [../runs/](../runs/). Each lesson
names the run that produced it, the RIDM surface it touches, and the change it suggests. One
lessons file exists per sprint of ten runs.

Section numbers cited in this file and in this sprint's run logs refer to RIDM 29, the
specification version under evaluation during the sprint.

Consolidation status: L110 through L113 are consolidated into RIDM 30, released 2026-09-05.
The next sprint's lessons start in `lessons/LESSONS_SPRINT_0017.md`.

The sprint's dominant signal: eight of ten runs scored, tying the second-best sprint, with
the high band four of five and every hit instrument-led or frame-led. Six wins came from
building and anchoring an instrument inside the run (a sky-chart projection fit, a
finite-difference replication, a numerical contour integration on a same-topology path, an
exhaustive game-tree solver validated by perft and known mates, an unfolding tracer with an
algebraic identification), and two from frame work (a classic restated with one changed
element, a stem missing a standard hypothesis whose one redundant-looking qualifier did the
selecting). Both misses ran against keys with checkable defects: a generated item whose key
denies a textbook theorem with an invented exception, and a computational item whose key
miscalculates the length of the trajectory in its own figure. The misses still carry
lessons, because in each case the framework held a rule that would have predicted or
refuted the key and the rule was applied at the wrong strength or not at all. Two items
were skipped without run numbers, one at the user's direction after the reasoning looped
and one when the harness safeguard blocked a reply about song lyrics.

## L110. On a generated item the filter is decisive where the population converges (Q000156)

RIDM 29 surface: Sections 19 and 24, Control Law 17. The framework collapses the
pool-filter signal to narrative tier on generated stems because reference models scatter
on incoherent stems. That reasoning is about convergence, not about the rigor class. A
generated sub-question that restates a standard theorem is a stem the reference population
converges on, so the item's survival is decisive evidence that the key sits off the
theorem, and the generator's habit of rejecting a universal claim with an invented
exception is the referent to predict. The keyed negation was generated as a candidate and
discharged by consensus, which on a filtered pool is the argument that runs backwards. The
filter's strength follows the reference population's convergence on the statement; the
rigor class only predicts where that convergence lives.

## L111. Pre-compute the ring the answer must lie in, and price transcription (Q000158)

RIDM 29 surface: Sections 21 and 48, Control Laws 24 and 25. A well-posed computational
item carried a key transcribed from a published figure, and the transcribed number was not
a possible value at all: every developed vertex position was an integer combination of unit
vectors at multiples of one angle, so the squared length had to lie in a specific ring, and
the key's did not. That structural fact was known before the reveal and would have refuted
the verdict exactly the moment it appeared, which is the representability audit applied to
an oracle. Two consequences. First, the oracle-discipline rule that differences a
disagreement extends to a representability check: compute, before commitment, the ring,
field, or value class the true answer must inhabit, so a defective verdict is refuted by
membership and not only by offset. Second, a key transcribed by hand or tool on a
well-posed item carries a componentry allowance like a multi-step chain does; the high band
was right for the derivation and blind to the referent.

## L112. A tool-derived key reflects the depth the author ran it to (Q000155)

RIDM 29 surface: Sections 19 and 21, Control Law 24. A game-tree item's true value was
proven by an anchored exhaustive solver, and an engine reported three successive values as
its depth grew before converging on the proven one. The author's referent was the engine,
and the key's own rationale says it must run for a while to reach the optimal value. This
is implementation distance in a new costume: when the key is produced by an iterative tool,
the pre-convergence values are the predictable referent variants, computed pre-reveal, and
the band opens at the referent's convergence risk rather than at the derivation's strength.
The same run re-confirmed the anchoring rule: the faster solver failed a known-mate anchor,
which exposed a table bug that would have produced a wrong "no mate" verdict at the live
depth.

## L113. A scoped representation must denote the committed object exactly (Q000160)

RIDM 29 surface: Section 30, Control Law 26. A commitment named a compound correctly and
stated its bonding explicitly, then offered a "commonly written" alias that under strict
nomenclature denotes a different regioisomer. The claim survived because the explicit
structure disambiguated it, but the alias was not a representation of the claim; it was a
second candidate wearing the costume of one. One claim under scoped representations
requires each representation to denote the same object under the domain's strict
conventions, and a loose alias is a componentry risk to be dropped, not coverage to be
added.
